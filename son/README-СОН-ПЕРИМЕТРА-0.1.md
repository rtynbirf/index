# СОН-ПЕРИМЕТРА-0.1 · ночной сторож флота

Волна 2026-11-21 · район СИНГУЛЯР/СВЯЗЬ · организация rtynbirf (80 репо, все публичные).

## Философия: сон — не смерть

Совет района №5 сказал коротко: живое ядро — **singulyar, cell-swarm, index, khozyain, release-vault**; остальным — **СОН, не смерть**: автоматы перевести на расписание раз в сутки. Никто не удаляется, никто не хоронится. Спящий репо — это не мёртвый репо: он просто дышит реже, раз в сутки по расписанию, а не каждые минуты.

У владельца нет слуха, зрения и рук — периметр смотрит машина. Сторож — это глаза периметра, не могильщик. Он не удаляет, не выключает, не судит. Он обходит весь флот раз в ночь и записывает: кто на какой голове стоит, кто не отзывается. «Не отвечает» значит «не отвечает» — таймаут или сеть, а не смерть. Похорон не будет.

## Что делает сторож

Файл `son/son_perimetra.py`, два режима:

- **check** — обход флота из `son/fleet.json` (ядро — по их веткам: `singulyar@rumu`, `cell-swarm@main`, `index@main`, `khozyain@main`, `release-vault@main`; спящие 75 — по HEAD, имя default_branch сторож узнаёт сам через `git ls-remote --symref`). Построчный вывод + итоговая сводка + время обхода.
- **write --out-dir D** — тот же обход, плюс два файла: датированный `сон-YYYY-MM-DD.json` и `last.json` (тот же отчёт; перезаписывается — это его собственный файл). Если рядом лежит прошлый `last.json`, в отчёт попадает графа «с_прошлой_ночи»: кто сменил голову, кто молчал и в прошлый раз.

Как спит сторож: обход строго последовательный — 80 репо по одному, таймаут 15 секунд на репо, никакого параллельного шторма. Каждое репо — один `git ls-remote`, без токена, без api.github.com (там лимит 60 запросов/час без токена — на 80 репо не хватит; у ls-remote лимита нет). Суммарное время обхода печатается.

Коды выхода: `0` — обход прошёл, факты показаны (дрейф — норма, не ошибка); `2` — сверка не состоялась: waves.json недоступен или не ответил ни один репо.

## Как читать отчёт

Графы `сон-YYYY-MM-DD.json`:

- **когда** — момент обхода в UTC.
- **флот** — сколько всего, сколько ядро, сколько спящие, сколько вошло в обход.
- **якоря** — источник якорей (`index@main registry/waves.json`), число волн, доступен ли реестр.
- **обход** — отвечено / не отвечает / время обхода / вежливость (последовательно, таймаут 15 с).
- **совпадают** — репо, чья голова совпала с якорем волны: СОВПАДАЕТ.
- **уехали** — голова не совпала с якорем: УЕХАЛА (дрейф автоматов — норма; рядом дата якоря и волна, с которой сверялись).
- **вне_якорей** — у репо нет якоря в waves.json: вне якорей (спит). Голова записана — сравнивать её можно с прошлыми ночами.
- **сверка_невозможна** — waves.json был недоступен: головы записаны, сверка честно не обещана.
- **не_отвечает** — таймаут/сеть. Не смерть: в следующую ночь сторож постучит снова.
- **с_прошлой_ночи** — сравнение с прошлым `last.json`: кто шевельнулся, кто молчит вторую ночь.
- **границы** — честные границы самого отчёта, всегда при нём.

## Честные границы

- Сторож ходит `git ls-remote` без токена. Он видит SHA голов веток — и всё.
- Даты последних пушей он **не видит** (это чужой API, лимиты без токена). Поэтому дрейф считается **относительно якорей** `registry/waves.json` и **прошлых отчётов** (`last.json`), а не по времени пуша. УЕХАЛА — не диагноз: автоматы района пушат каждые минуты, это их нормальная жизнь.
- Якоря есть пока только на `singulyar@rumu` и `cell-swarm@main` (3 волны от 2026-11-21). Остальные репо — вне якорей; для них дрейф измеряется прошлыми ночами, как только накопятся отчёты.
- Отчёт в артефакте прогона Actions живёт ~90 дней. Вечную историю даёт только коммит отчётов в репо (шаблон шага — в комментарии workflow).
- Сторож не проверяет содержимое, тесты и CI других репо. Он смотрит только на головы веток. Судят репо их собственные палаты.

## Запуск руками

```bash
# построчная сверка без файлов
python3 son/son_perimetra.py check --only singulyar,cell-swarm,index,khozyain,release-vault

# полный флот с отчётом
python3 son/son_perimetra.py write --out-dir son-otchet/
```

Токен не нужен нигде: всё публичное, всё через git ls-remote и raw.githubusercontent.com.
